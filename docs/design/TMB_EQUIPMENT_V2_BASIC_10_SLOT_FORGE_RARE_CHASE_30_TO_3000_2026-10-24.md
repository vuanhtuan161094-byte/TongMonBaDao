## 0. First settle a critical false dichotomy
**Basic gear supply** should enable everyday playable disciples to equip *legitimately crafted/assigned* items in **all ten ordinary slots**; **HIẾM combat loot** should deliver stronger affixes, named variants and select legal set pieces. One does not replace the other.
- [L] Ordinary slot IDs: `weapon,head,armor,cloak,bracers,gloves,belt,boots,pendant,ring`. [L] Grade1..12 and equipment realm1..30 are distinct axes. Only six positional slots `head,armor,cloak,bracers,belt,boots` can be part of set families. Separate three Phù / two Pháp Bảo / four consumables, all not redefined here.
- [L] Sect owns EVERY gear item instance in ONE canonical Warehouse; disciple only assignee. No private loot bag, no equip free cloning when reassigned, inventory reserve/locks and anti-downgrade complete-set guard.
- [S] `EquipmentSystem` in main currently supports only three legacy `weapon/armor/talisman` slots and five P2 recipes. V2 ten-slot code, source pool registry and 96 set template instances are DESIGN, not Godot deployed or tested.
- [L] Special Forge architecture: Luyện Khí Điện Lv1 basics/repair, Lv10 auto repair, Lv20 material refinement, Lv30 monster-material forge, Lv50 reforge option, Lv75 advanced set/special chances, Lv100 deeper rare-line mastery. THIS IS MILESTONE DIRECTION — time, quality rates, blueprint eligibility and number of concurrent orders need separate approval. Lv75 does NOT globally bar every low-rank set; existing full set lineages remain 24 distinct rules.
- [L] 24 named lineages × 4 fixed positional pieces = 96 authored piece definitions, including Hỗn Độn **Thần only**. Source truth from the 2026-10-08 set matrix, no invented titles, no 5-piece sets or generic "any four armor items".

- named **blueprint page** must be first registered and have valid source and sink (not currently a ResourceRegistry ID). A safe future set recipe schema: `forge_v2:set:<lineage_id>:<slot>` with `gear_v2:set:<lineage_id>:<slot>` output, explicit item realm, generation, 1 base `thanh_thiet` +1 base `linh_moc` +2 legal registered monster material of its source camp, 1 registered piece-blueprint consumed/reserved according to policy, actual duration/quality/profession/Forge milestone. Recipe output's set lineage/position MUST be exact source catalog, and set generation cannot mix.

### 4.1 Rare chase count is not basic availability
Under **HIẾM** synthetic reference, 30 hunters×300 full monsters/20 camps, **360 normal kills+3 Elite+0.25 Boss per sim-hour** yielded ≈`0.297425 gear events/h` =≈**214.15 rare item events/720 sim-h (30 simdays)**. 40% hypothetical role-fit gives≈86 relevant *items*, NOT 300 correctly positioned basics, NOT guarantee of four same-lineage set pieces. No World Combat with these kill rates was executed. If 1,000/3,000 roster shares only one TTL world, the rare supply is unchanged, whereas basic demand multiplies — use normal Forge and hand-me-downs, not 3,000 combat characters on one map.
**Suggested non-lock policy for 30-map roster:** prioritize valid weapon+armor+boots for deployed frontliners (protect survivability/range/mobility), then fill missing other slots from lawful base Forge as resources/orders arrive; focus rare loot on main DPS/tank/healer/elite Boss squads with explicit user loadout locks and set-preservation. A non-hunting worker may use C-profession lines only if real production consumer exists; “+X% output” from fabricated item is disallowed.
**Avoid double-currency and over-collection:** personal Spirit Stone/Contribution/Tu Vi sources remain separate from item loot; no auto "Boss gives 30 equipment" for 30 helpers. Rare salvage/upgrading/market sources deferred under canonical Forge roadmap, not used as imagined inputs/outputs today.
